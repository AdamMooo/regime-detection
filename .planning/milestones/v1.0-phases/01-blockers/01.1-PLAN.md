# Plan 01.1: Fix LABEL_MAPPING Critical Issue

**Objective:** Resolve critical code review finding (CR-01) — LABEL_MAPPING incomplete for all possible regime names and N_STATES=4 default creates unmapped regime names.

---

## Tasks

### Task 1: Expand LABEL_MAPPING to cover all regime names

**Current state:** LABEL_MAPPING only has 3 entries (Low-Vol, Medium-Vol, High-Vol)

**Problem:** N_STATES=4 (default) generates regimes named ['Low-Vol', 'Moderate', 'Elevated', 'Crisis'], but LABEL_MAPPING doesn't have entries for 'Moderate', 'Elevated', 'Crisis'.

**Action:**
1. Read config.py REGIME_NAMES and VOL_BRACKETS to understand all possible regime names
2. Expand LABEL_MAPPING in config.py to include entries for all regime names that can be generated:
   - 'Low-Vol' → 'LOW_VOL'
   - 'Medium-Vol' → 'MED_VOL' (for 3-regime mode)
   - 'Moderate' → 'MOD_VOL' (for 4+ regime mode)
   - 'Elevated' → 'ELEV_VOL' (for 4+ regime mode)
   - 'High-Vol' → 'HIGH_VOL' (for all modes)
   - 'Crisis' → 'CRISIS_VOL' (for 4+ regime mode)
   - Add entries for 5/6-regime mode: 'Very-Low', 'Elevated-Vol' prefix variants, etc.

**Commit:** "fix(config): expand LABEL_MAPPING to cover all possible regime names"

---

### Task 2: Set N_STATES default to match 3-regime architecture specification

**Current state:** N_STATES = 4 (line 51 of config.py)

**Problem:** Architecture specifies "3 regime target" (CLAUDE.md), ROADMAP.md says "3 regimes expected", but default is 4. This creates configuration mismatch and makes CR-01 manifest immediately.

**Action:**
1. Change N_STATES default from 4 to 3 on line 51
2. Update comment to explain: "3 regimes (Low-Vol, Medium-Vol, High-Vol) as per production specification"
3. Note N_STATES_RANGE still includes 2, 3, 4 for model selection (BIC search can explore 4-regime option, but 3 is default)

**Commit:** "fix(config): set N_STATES=3 to match 3-regime production specification"

---

### Task 3: Validate LABEL_MAPPING covers all possible regimes via test

**Current state:** No test validates LABEL_MAPPING completeness

**Action:**
1. Add unit test in tests/test_bot_integration.py: `test_label_mapping_completeness()`
2. For each N_STATES in [2, 3, 4, 5, 6]:
   - Get regime names from REGIME_NAMES[N_STATES]
   - Verify all regime names have entries in LABEL_MAPPING
   - If any regime name missing, test fails with helpful message showing gap
3. This prevents CR-01 from regressing (if someone changes VOL_BRACKETS or REGIME_NAMES, test catches it)

**Commit:** "test(bot_integration): add test_label_mapping_completeness for all N_STATES"

---

### Task 4: Update error message in signals.py

**Current state:** KeyError raised if regime_name not in LABEL_MAPPING, but message doesn't mention which regime names ARE valid

**Action:**
1. Catch KeyError in compute_signals() for unmapped regime names
2. Raise with helpful message: "Regime '{regime_name}' not in LABEL_MAPPING. Valid regimes: {list(LABEL_MAPPING.keys())}"
3. This helps users debug configuration mismatches quickly

**Commit:** "fix(signals): improve error message for unmapped regime names"
