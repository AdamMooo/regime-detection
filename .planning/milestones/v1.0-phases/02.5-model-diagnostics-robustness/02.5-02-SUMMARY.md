# Phase 2.5 Plan 02 Summary: Feature Selection Bias Analysis

Fix implicit overfitting in feature selection. Original 7 features were selected on full dataset (2010–2026), creating lookahead bias. Re-selected features on held-out train set (2010–2020), evaluated on held-out test set (2021–2026). Result: switching to 6 new features improves OOS performance and regime stability.

## Objective Achievement

**Original Problem:** 7 features selected on full dataset (2010–2026) may be overfitted to entire history, not generalizable to future OOS data.

**Solution Executed:** 
1. Split data: Train (2010–2020, 2706 trading days) vs Test (2021–2026, 1324 trading days, held-out)
2. Selected new features on train set only using correlation-based filtering (>0.8 threshold)
3. Evaluated both original 7 and new features on held-out test set
4. Compared: regime accuracy, dwell time, Kupiec POF p-value, Christoffersen p-value

**Result:** New 6-feature set shows measurable improvements, recommended for production.

## Causality Guarantees Maintained

All feature engineering uses expanding windows (past data only):
- Standardization: `expanding_standardize()` uses only rows [0..t] at time t
- Feature selection: Performed on train set (2010–2020) in isolation
- Evaluation: Test set (2021–2026) never seen during selection or training
- PCA: Fit incrementally on train; test projected using final PCA
- HMM inference: Uses filtered probabilities (forward-pass only, no smoothing)
