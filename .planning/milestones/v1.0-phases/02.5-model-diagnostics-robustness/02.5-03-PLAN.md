## Key Facts

**Problem:** BIC selected K=4 with marginal improvement (3.1% over K=3). May be overfitting to in-sample data.

**Solution:**
1. Walk-forward validate K=3 and K=4 on OOS data
2. Compare metrics: in-sample likelihood, OOS likelihood, regime stability, regime count variability
3. Apply parsimony rule: if BIC improvement < 2%, use K=3
4. Verify K=3 aligns with bot integration (Low/Med/High = 3 regimes)
5. Enforce chosen K in production code (config.py N_STATES)

**Causality:** Walk-forward validation is forward-pass only, no lookahead.

  <files>select_k_via_crossval.py</files>
  <action>
Create a standalone K regime count selection script that:

1. **Load data**:
   - Full dataset: 2010–2026 market data (4093 trading days)
   - Split: train (2010–2020, 2520 days) and test (2021–2026, 1573 days)

2. **In-sample model selection (baseline)**:
   - Train on full dataset (2010–2026)
   - Run BIC model selection: compare K=2, 3, 4, 5
   - Log BIC scores and differences (ΔK4-K3, ΔK3-K2, etc.)
   - Record: which K chosen by BIC, improvement percentages
   - Compute likelihood for each K on training data

3. **Walk-forward validation for K=3**:
   - Walk-forward windows: expand from 2010 to each test date
   - Train: K=3 HMM on expanding train window
   - Test: predict regime labels on 1 day ahead
   - Record: OOS likelihood, regime count, regime label (is it consistent with previous day?)
   - Compute regime dwell time (how many days same regime label persists)
   - Aggregate: mean OOS likelihood, mean regime count (should be 3±ε), median dwell time

4. **Walk-forward validation for K=4**:
   - Same as K=3, but with K=4 HMM
   - Record: OOS likelihood, regime count, regime label, dwell time
   - Aggregate metrics

5. **Regime stability analysis**:
   - For K=3: measure label variance (do regime labels flip frequently?)
   - For K=4: measure label variance
   - Compute regime entropy (H = -Σ p_k log(p_k) over regime probabilities)
   - Higher entropy = less certain regime assignments; lower is better
   - Record entropy for both K=3 and K=4

6. **Parsimony test**:
   - Calculate BIC improvement: (BIC_K3 - BIC_K4) / BIC_K3 * 100
   - If improvement < 2%, recommend K=3 (Occam's razor)
   - If improvement >= 2%, recommend K=4 (statistically meaningful)
   - Document rule in code: "Parsimony threshold: 2% BIC improvement"

7. **Bot integration check**:
   - Verify that K=3 or K=4 can map to 3 bot regimes (Low/Med/High)
   - If K=3: direct mapping (Regime 0→Low, 1→Med, 2→High)
   - If K=4: must merge one regime; document which and why
   - Check LABEL_MAPPING in signals.py for compatibility

8. **Output**:
   - Print comparison table:
     | Metric | K=3 | K=4 | Winner |
     |--------|-----|-----|--------|
     | In-sample BIC | X | Y | K=3 if X smaller |
     | BIC improvement % | - | Z% | K=3 if Z < 2% |
     | OOS likelihood (mean) | L3 | L4 | Higher wins |
     | Regime count (mean) | C3 | C4 | Closer to K wins |
     | Regime dwell time (median days) | D3 | D4 | Higher wins |
     | Regime entropy | E3 | E4 | Lower wins |
   - Save detailed report to regime_count_selection_report.txt
   - Plot: regime count over time (K=3 vs K=4) showing stability
   - Plot: OOS likelihood evolution (K=3 vs K=4) over test period

9. **Final recommendation**:
   - If K=3 wins majority of metrics (≥4 out of 6), recommend: "Use K=3 (meets parsimony and bot integration requirements)"
   - If K=4 wins majority, recommend: "Use K=4 (statistically better OOS performance justifies complexity)"
   - If tied, recommend: "Use K=3 (parsimony + bot integration alignment)"

10. **Causality guarantee**: Walk-forward is forward-pass only, expanding window (no lookahead), no future data.

Document all findings in regime_count_selection_report.txt and console output.
