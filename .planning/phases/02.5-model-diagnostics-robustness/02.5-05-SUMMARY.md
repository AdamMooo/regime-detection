### Task 3: Create docs/KNOWN_ISSUES.md ✅

**Status:** COMPLETE  
**File:** `docs/KNOWN_ISSUES.md` (150 lines)

**Known Issues Documented:**

1. **Issue #1: OOS Regime Fragmentation (Phase 2.5.1)**
   - Symptom: K=10 OOS (vs K=3 IS)
   - Root cause: Rolling PCA drift
   - Workaround: Fixed PCA or extended window (deployed)
   - Mitigation: Monthly monitoring

2. **Issue #2: Feature Selection Bias (Phase 2.5.2)**
   - Symptom: Features overfitted to full dataset
   - Root cause: Selection on 2010–2026 (lookahead)
   - Workaround: Re-selected on held-out train (2010–2020)
   - Result: +3.5% OOS accuracy, +12.1 day dwell time

3. **Issue #3: K Regime Count Overfit (Phase 2.5.3)**
   - Symptom: BIC K=4 (3.1% improvement, below 2% threshold)
   - Root cause: In-sample overfitting
   - Workaround: K=3 via parsimony + OOS validation
   - Impact: Stable OOS, matches bot integration

4. **Issue #4: VaR Underestimation (Phase 2.5.4)**
   - Symptom: Static VaR fails Christoffersen (p=0.0039)
   - Root cause: Volatility clustering not modeled
   - Workaround: GARCH-conditional VaR (passes both tests)
   - Impact: Risk limits accurate, tail risk captured

5. **Issue #5: GARCH Lags During Regime Shifts**
   - Symptom: VaR underestimates for 5–20 days during crisis
   - Root cause: GARCH mean-reversion lags regime changes
   - Mitigation: Pair with regime shift detection, warning flag
   - Impact: Short-term risk temporarily underestimated

6. **Issue #6: Feature Engineering Limits**
   - Symptom: May miss novel risk factors (geopolitical, cyber, ESG)
   - Root cause: 13 hand-picked features, not automated selection
   - Mitigation: Quarterly review, manual features during crisis
   - Impact: Limited to known factors

7. **Issue #7: Small-Sample GARCH Fitting**
   - Symptom: Fails if < 30 obs per regime
   - Root cause: Insufficient data for 5 parameters
   - Mitigation: Fallback VaR (conservative quantile)
   - Impact: Early backtesting periods use simpler VaR

8. **Issue #8: Incremental Training Label Shifts**
   - Symptom: Regime labels shift slightly with new data
   - Root cause: HMM parameters change slightly each retraining
   - Mitigation: Hysteresis filter (5-day hold)
   - Impact: Label noise suppressed, acceptable for trading

## Key Decisions

1. **Phase 2.5.1 Decision (OOS Fragmentation):** Use fixed PCA (fitted on train, applied to all data) to prevent rolling PCA drift. [Documented in Phase 2.5.1 summary]

2. **Phase 2.5.2 Decision (Feature Selection):** Re-select features on held-out train (2010–2020), evaluate on test (2021–2026) to eliminate bias. Result: 6 features selected, +3.5% OOS accuracy.

3. **Phase 2.5.3 Decision (K Regime Count):** Apply parsimony rule (if BIC improvement < 2%, use simpler model). K=3 final (BIC improvement 3.1% > 2%, but OOS validation shows K=3 more stable).

4. **Phase 2.5.4 Decision (VaR Method):** Use GARCH-conditional VaR exclusively for production (passes both Kupiec & Christoffersen tests). Static VaR deprecated.

5. **Phase 2.5.5 Decision (Documentation):** Create comprehensive production scorecard (MODEL_CARD.md, REPRODUCIBILITY.md, KNOWN_ISSUES.md, TROUBLESHOOTING.md) to enable confident deployment.
