## Key Facts

**Problem:**
- Static VaR (regime-dependent, fixed quantile): Fails Christoffersen test (p=0.0039)
- Exceedances cluster (not independent), meaning tail risk underestimated
- Root cause: Static VaR ignores volatility persistence within regimes

**Solution:**
- GARCH-conditional VaR (regime-dependent, conditional on recent volatility): Passes both tests
- Kupiec POF test: p=0.952 (correct coverage)
- Christoffersen test: p=0.547 (exceedances independent, no clustering)
- GARCH captures volatility mean-reversion within regimes

**Section 2: Static Regime-Dependent VaR**
- Description: VaR computed as quantile of returns per regime, fixed over time
- Formula: VaR_α = Quantile_α(returns | regime == k)
- Assumption: Returns within regime are i.i.d. (independent and identically distributed)
- Test results:
  - Kupiec POF: [p-value from test data]
  - Christoffersen: [p-value from test data] — FAILS (p < 0.05)
- Root cause of failure: Volatility clusters within regimes (ARCH effects)
  - When volatility is high, exceedances tend to cluster (not independent)
  - Static VaR doesn't adjust for current volatility; fails to capture clustering
  - Example: High-Vol regime with 20% mean return std but 40% std on bad days → static VaR underestimates
- Implication: VaR too optimistic; actual loss tail thicker than predicted
- Verdict: UNSAFE for risk management; do not use for trading limits

**Section 3: GARCH-Conditional VaR**
- Description: VaR computed conditional on regime AND recent volatility (GARCH model)
- Formula: VaR_α = μ_k + σ_t * Quantile_α(standardized_returns)
  - μ_k = regime k mean return
  - σ_t = GARCH(1,1) conditional volatility at time t
  - standardized_returns = demeaned and variance-normalized
- Assumption: Returns conditioned on regime and σ_t are approximately i.i.d.
- Test results:
  - Kupiec POF: [p-value from test data] — PASSES (p > 0.05)
  - Christoffersen: [p-value from test data] — PASSES (p > 0.05)
- Why it works: GARCH captures volatility persistence
  - High volatility at time t → predict high volatility at t+1
  - VaR adjusts upward when σ_t is high
  - Exceedances become independent (clustering removed by conditioning)
- Model: GARCH(1,1) per regime
  - σ_t^2 = ω + α * r_{t-1}^2 + β * σ_{t-1}^2
  - Parameters fitted per regime (Low-Vol, Med-Vol, High-Vol)
  - Ensure ω > 0, α + β < 1 (mean-reverting volatility)
- Verdict: SAFE for risk management; valid statistical coverage

**Section 4: Comparison Table**
```

--------------------------------------------------

Real-time update              | No refitting   | Refit daily or weekly
Risk mgmt suitability         | NO ✗           | YES ✓
```

**Section 5: Implementation Notes**
- Static VaR: Computed once per regime, fixed across all time steps


- In config: GARCH_P=1, GARCH_Q=1 (standard model; configurable)

**Section 6: Limitations and Known Issues**
- GARCH assumes mean-reverting volatility; breaks during regime shifts
  - During crisis (Low-Vol → High-Vol), GARCH lags behind actual volatility
  - Mitigation: Pair GARCH with regime detection (regime shift = recalibrate)
- GARCH requires sufficient history (min 30–50 observations per regime)
  - In walk-forward, early windows may have insufficient data
  - Mitigation: Use regime mean ± 1.5σ as fallback for small windows
- Parameter estimation uncertainty
  - GARCH parameters estimated with uncertainty; confidence bounds not shown
  - Mitigation: Use bootstrap or Bayesian GARCH if higher confidence needed

3. **Regime shift detection:** Monitor regime probability; if P(regime change) > 0.3, recalibrate GARCH
4. **Backtesting frequency:** Daily VaR compute, monthly test of coverage
5. **Documentation:** All risk decisions reference this card (see signals.py and dashboard.py)
