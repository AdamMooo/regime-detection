<objective>
Implement DIAG-04: regime-conditional forward return analysis with Kruskal-Wallis
statistical test. Add `analyze_forward_returns()` function to `src/core/evaluation.py`,
integrate it into `scripts/analysis/analyze_regime_characterization.py`, and write
`tests/test_regime_economic_validity.py`.

This is a pure measurement plan: no model changes, no feature changes, no pipeline changes.
Forward returns are diagnostic outputs only — never added as model features.
</objective>

<tasks>

<task id="1" type="auto" name="Add analyze_forward_returns to evaluation.py">
Add new function `analyze_forward_returns(results, market, horizons=[1, 5, 21], assets=['SPY', 'EEM', 'TLT', 'HYG'])` to `src/core/evaluation.py`.

Function behavior:
- Compute forward log returns for each asset at each horizon (1d, 5d, 21d)
- Merge with regime labels from results DataFrame
- Run Kruskal-Wallis test (scipy.stats.kruskal) across regimes for each asset/horizon combo
- Return a dict with keys like `(asset, horizon)` → `{'median_returns': {regime: val}, 'kw_stat': float, 'kw_pvalue': float}`
- Print a formatted table (regime rows, asset/horizon cols, p-values only — no auto-flag)
- Add `analyze_forward_returns` to the module's `__all__`

Inputs:
- `results`: DataFrame with `regime_name` column and DatetimeIndex
- `market`: DataFrame with columns `{ASSET}_close` for each asset (e.g., `SPY_close`)
- `horizons`: list of ints (days)
- `assets`: list of asset tickers

Constraints:
- Forward returns must be computed from market data only (no regime info used)
- Forward returns must NOT be added as model features (diagnostic only)
- Function must be callable from the characterization script
</task>
